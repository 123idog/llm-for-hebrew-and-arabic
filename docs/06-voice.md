# 6. Voice: Speech-to-Text and Text-to-Speech

---

## Transcribing Hebrew and Arabic sales calls

**Recipe that held up:**
- Use the **strong** multimodal model with file upload, not the fast one. The fast model fell into **repetition loops** (the same sentence over and over) on about 7% of calls, and those runs were marked successful.
- Give the model an escape hatch: a fixed token like `NO_CONVERSATION` for voicemail, silence and wrong numbers, so it doesn't invent a call.
- Normalise speaker labels after transcription.
- Don't cap the thinking budget too low. It produced empty responses.

**Cheap QA that catches loops and hallucinations:** characters per second. Real Hebrew speech ran at roughly 13–16 chars/sec (p95 about 16). Flag any transcript above 30; it's almost always a loop.

**Cost reference:** a 30-minute Hebrew call cost roughly $0.35 at standard pricing and about half that on a batch tier.

**Output language can differ from input.** Arabic calls were transcribed in Arabic, while the analysis was written in Hebrew for the managers reading it. Decide that explicitly per field.

## Check language support per model, not per vendor

- Within one TTS vendor, several "multilingual" models returned `400 unsupported_language` for Hebrew. Check the language list for each **model**.
- A voice-agent platform defaulted to **English** speech recognition, and accepted any model/language combination with a 200, including combinations that don't work. Only one speech-recognition provider actually validated the locale. Test with a real Hebrew call before trusting a configuration screen.

## Model bake-offs need trap scenarios

For a Hebrew voice sales agent, three LLMs were run through scenarios built to catch specific failures (prices across seasons, totals that need arithmetic):
- one invented a weekly total that doesn't exist;
- one quoted the wrong season's price and wrote broken Hebrew;
- one passed all three.

Failures were **non-deterministic**, and a keyword-based auto-check missed one that a human caught. Run each scenario several times, and have a native speaker read the output.

## Pronouncing names in Hebrew TTS

Hebrew is written without vowels, so TTS guesses pronunciation, and proper names (especially foreign ones) are where it guesses wrong.

What we observed:
- **plain Hebrew:** good most of the time (roughly 95%), but inconsistent across runs;
- **names in Latin script** inside Hebrew text: worse (roughly 85%), and names of Hebrew origin broke;
- **mixing scripts by name origin:** still failed on some foreign names.

The direction being tested is **full vowel marks (nikud) on proper names**, prefixes included, generated by the script model with examples across name origins. Treat it as a hypothesis until it's measured on your names.

**Don't guess pronunciation-dictionary entries.** A guessed phonetic entry made one name sound worse than the default. Add an entry only for a word a human has confirmed sounds wrong, and have a human approve the fix.

## Automated audio QA

For generated voiceovers, a second model listens to the audio and scores it; anything under a threshold is regenerated before a human sees it. It catches mispronunciations and cut-offs cheaply, but the threshold must be calibrated against a native listener's judgment.
